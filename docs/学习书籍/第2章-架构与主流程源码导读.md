## 2.2 程序入口：`main.py`

`freqtrade/main.py:31-79`，全部逻辑就是一次大的 `try/except`：

```python
def main(sysargv=None) -> None:
    try:
        setup_logging_pre()                       # 先初始化日志
        arguments = Arguments(sysargv)            # 解析命令行
        args = arguments.get_parsed_arg()
        if args.get("version"):
            print_version_info()
        elif "func" in args:
            return_code = args["func"](args)       # ★ 关键：子命令函数表
        else:
            raise OperationalException("...requires a subcommand...")
    except KeyboardInterrupt: ...                  # Ctrl+C 优雅退出
    except ConfigurationError as e: ...             # 配置错误 → 人话提示
    except Exception: logger.exception(...)         # 兜底，打印完整堆栈
    finally: sys.exit(return_code)
```

**设计亮点（新手值得学）**：
- `args["func"](args)` —— 命令行的 `trade` / `backtesting` / `hyperopt` 各自对应一个函数，注册进同一个字典，分发时查表即可，不用写一长串 `if/elif`。
- `try/except` 分层：先接具体异常，最后 `Exception` 兜底，保证程序**总是**以可解释的方式退出。
- 第 12 行还检查了 Python 版本 ≥ 3.11。

`freqtrade trade` 会走到哪里？它最终构造 `Worker` 并调用 `worker.run()`（见下）。

## 2.3 主循环：`worker.py`

### 2.3.1 永动循环

`freqtrade/worker.py:76-81`：

```python
def run(self) -> None:
    state = None
    while True:                                   # ★ 机器人的心跳
        state = self._worker(old_state=state)
        if state == State.RELOAD_CONFIG:
            self._reconfigure()                   # 支持热重载配置
```

### 2.3.2 状态机 `_worker`

`worker.py:83-143`。机器人是个**状态机**，状态来自枚举 `State`（`RUNNING / PAUSED / STOPPED / RELOAD_CONFIG`）：

- 状态变化时：记日志、通知 Telegram；首次进入 RUNNING 时调 `freqtrade.startup()`（补齐数据库、校准止损等，`freqtradebot.py:262`）。
- `STOPPED`：调 `_process_stopped`（只处理收尾），继续睡。
- `RUNNING/PAUSED`：调 `_process_running` → `self.freqtrade.process()`（**真正的业务**，`worker.py:197-199`）。
- 错误处理（`worker.py:200-212`）：
  - `TemporaryError`（网络抖动）→ 等几秒重试，**不退出**；
  - `OperationalException`（致命错误）→ 发 Telegram 告警 + 状态置 STOPPED。

### 2.3.3 节流 `_throttle`：多久跑一轮

`worker.py:145-187` 是理解"机器人节奏"的关键：

```python
result = func(*args, **kwargs)                 # 先干活
sleep_duration = throttle_secs - time_passed   # 再补齐睡眠，保证每轮至少 throttle_secs 秒
if timeframe:
    next_tf = timeframe_to_next_date(timeframe)      # 下一根K线何时出现
    ...
    sleep_duration = min(sleep_duration, next_tf_with_offset)  # 最多睡到下一根K线开盘+1s
sleep_duration = max(sleep_duration, 0.0)
self._sleep(sleep_duration)
```

**结论**：`process_throttle_secs`（默认 5 秒，`worker.py:58`）决定了轮询频率；同时保证**新 K 线一出来 +1 秒**就会醒来处理——这就是策略能"踩点"的原因。

## 2.4 核心业务：`FreqtradeBot.process()`

`freqtrade/freqtradebot.py:304-360`，这是整个项目**最重要的一段**，每轮循环按固定顺序执行：

```python
def process(self) -> None:
    self.exchange.reload_markets()                    # ① 检查交易所市场信息是否要刷新
    self.update_trades_without_assigned_fees()        # ② 补算手续费

    trades = Trade.get_open_trades()                  # ③ 从数据库读所有持仓
    self.active_pair_whitelist = self._refresh_active_whitelist(trades)  # ④ 刷新监控币种列表

    self.dataprovider.refresh(                        # ⑤ 拉最新K线（含策略需要的其他周期）
        self.pairlists.create_pair_list(self.active_pair_whitelist),
        self.strategy.gather_informative_pairs(),
    )
    self.strategy.bot_loop_start(...)                 # ⑥ 策略的"每轮钩子"
    self.strategy.analyze(self.active_pair_whitelist) # ⑦ ★ 跑你的策略：算指标+出信号

    with self._exit_lock:
        self.manage_open_orders()                     # ⑧ 处理挂单（超时/取消/替换）

    with self._exit_lock:
        trades = Trade.get_open_trades()
        self.exit_positions(trades)                   # ⑨ ★ 先管旧仓：该平的平
        Trade.commit()

    self.check_liquidation_warnings()                 # ⑩ 合约强平预警
    if self.strategy.position_adjustment_enable:
        self.process_open_trade_positions()           # ⑪ 补仓/减仓（DCA）

    if self.state == State.RUNNING and self.get_free_open_trades() > 0:
        self.enter_positions(free_trade_slots)        # ⑫ ★ 再开新仓
    self._schedule.run_pending()                      # ⑬ 定时任务（资金费、钱包快照）
    Trade.commit()                                    # ⑭ 全部写库
    self.rpc.process_msg_queue(...)                   # ⑮ 发出排队的通知
```

**必背顺序：刷新数据 → 分析策略 → 平旧仓 → 开新仓 → 落库 → 通知。**
（先平后开：保证新开仓时资金已释放。）

### 构造函数里发生了什么（`freqtradebot.py:94-219`）

启动时一次性准备所有零件，顺序很有讲究：

1. `ExchangeResolver.load_exchange` 连交易所（第 111 行）
2. `StrategyResolver.load_strategy` **动态加载你 user_data 里的策略类**（第 115 行）
3. `init_db(db_url)` 打开 SQLite（第 122 行）
4. `Wallets` 钱包、`RPCManager` 通知、`DataProvider` 数据、`PairListManager` 币种筛选（第 124-140 行）
5. 把 `dp`、`wallets` **挂到策略实例上**（第 145-147 行）——这就是策略里能写 `self.dp`、`self.wallets` 的原因
6. 初次刷新白名单（第 160 行）、创建 `_exit_lock` 防止"平仓逻辑和强平通知打架"（第 167 行）
7. `strategy.ft_bot_start()` → 调你的 `bot_start()`（第 198 行）
8. 任何一步失败 → `cleanup()` 后重新抛出（第 216-219 行），**保证不会留下半初始化的僵尸进程**

## 2.5 三个支撑件速览

### Exchange（`exchange/exchange.py`，4278 行）
- 通过 **ccxt** 库统一各家交易所 API：`get_candle_history` 取 K 线、`create_order` 下单、`fetch_order` 查单。
- **dry-run 也在这个类里模拟**：`create_dry_run_order`（第 1195 行）用本地逻辑伪造一张交易所订单——所以模拟盘和实盘走的是同一套代码，只是最底层"接单"不同。
- 各交易所差异（精度、最小下单量）通过 `amount_to_precision` / `get_min_pair_stake_amount` 等方法抹平。

### Persistence（`persistence/trade_model.py`）
- `Trade` 表 = 一笔交易的全部生命周期记录，关键字段（第 409-443 行）：
  `is_open`（是否持仓中）、`open_rate`（开仓价）、`close_rate`（平仓价）、`stake_amount`（投入本金）、`amount`（币数量）、`stop_loss`（止损价）、`exit_reason`（为什么平的仓）。
- **为什么必须持久化**：机器人随时可能重启，重启后从数据库读回 `Trade.get_open_trades()` 继续管理持仓——这就是 `process()` 第 ③ 步。

### RPC（`freqtrade/rpc/`）
- `rpc.py` 是统一出口，`telegram.py`、`api_server`（FreqUI 网页）、`webhook.py` 是不同渠道。
- 模式：业务代码只调 `self.rpc.send_msg({...})`，具体发到哪由配置决定——典型的"一层抽象解耦"。
