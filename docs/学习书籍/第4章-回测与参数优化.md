# 第 4 章 回测与参数优化

> 回测 = 让策略在历史数据上"重放"一遍。它是量化最重要的验证手段，也是最容易骗自己的手段。本章讲清楚 freqtrade 回测**到底怎么算的**，以及 hyperopt 怎么帮你找参数。

---

## 4.1 数据从哪来：`download-data` 与存储格式

```bash
freqtrade download-data --pairs BTC/USDT ETH/USDT --timeframes 5m 1h \
    --timerange 20250101- --exchange binance
```

- 下载逻辑在 `freqtrade/data/history/history_utils.py` 的 `download_data`（第 712 行）。
- 数据落盘在 `user_data/data/binance/`，默认 **feather 格式**（每对每周期一个文件，读写极快）。
- 回测读取入口：`load_pair_history`（`history_utils.py:45`）。
- **回测质量上限 = 数据质量**：数据缺一根，回测就可能给出错误信号。

## 4.2 回测引擎工作原理（`optimize/backtesting.py`）

### 整体流程

```
freqtrade backtesting 命令
  └─► Backtesting.start()                (backtesting.py:1906)
       ├─ 加载历史数据 load_bt_data()      (357)
       ├─ 跑策略算出全部信号（一次性预计算）(1825 backtest_one_strategy)
       └─ backtest()                      (1763) ★ 逐时间、逐币重放
            └─ 对每根K线调 backtest_loop() (1519)
```

### 单根 K 线上做什么（`backtest_loop`，第 1519-1579 行）

```python
# 1. 管理该币现有挂单（没成交的入场单会被超时取消）
# 2. 有新信号 & 有空闲仓位槽 & 该币没被锁 → _enter_trade() 开仓
# 3. 处理入场订单成交
# 4. 持仓中 → _check_trade_exit() 检查该不该平（信号/止损/ROI）
# 5. 处理出场订单成交
```

外层 `backtest()`（第 1787-1806 行）用 `time_pair_generator` 把**所有币按时间轴对齐**，同一时刻逐币处理——模拟真实世界"时间同时向前走"。

### 三个决定回测可信度的细节

1. **信号→下单有时滞**：策略在第 N 根 K 线收盘时出信号，**按第 N+1 根的开盘价成交**（模拟真实世界：K 线没走完你不知道它收在哪）。这是防"未来函数"的第一道墙。
2. **撮合规则**：限价单必须"价格穿过你的限价"才成交（`_get_order_filled`，第 787 行）；模拟手续费由 `set_fee`（第 268 行）设定。
3. **止损按最低/最高价触发**：做多时用当根 `low` 判断是否击穿止损（`_get_close_rate_for_stoploss`，第 597 行），做空用 `high`——不会出现"回测里止损总是差一点"的假象。

### 与实盘的诚实差距

| 回测假设 | 实盘现实 |
|---|---|
| 只有一档 K 线价格 | 有买卖盘、有深度，大单会冲击价格 |
| 排队瞬间成交 | 限价单可能挂很久或不成交 |
| 滑点可用 `--slippage` 粗估 | 突发行情滑点巨大 |
| 手续费固定一个值 | maker/taker 不同、有 VIP 等级 |

**结论：回测的作用是"证伪"（证明策略不行），不是"证明稳赚"。**

## 4.3 跑一次回测并读懂输出

```bash
freqtrade backtesting --strategy MyFirstStrategy \
    --timeframe 5m \
    --timerange 20250101-20250701 \
    --max-open-trades 3 \
    --stake-amount 100
```

核心指标怎么读：

| 指标 | 含义 | 警惕线 |
|---|---|---|
| **Total profit** | 总收益率 | 高≠好，先看下面几项 |
| **Win rate** | 胜率 | 与盈亏比配套看：40% 胜率也可能赚钱（赚大亏小） |
| **Avg profit** | 平均每笔收益 | 必须 > 2×手续费才有意义 |
| **Max drawdown** | 最大回撤 | **>20% 就要认真考虑你扛不扛得住** |
| **Trades 数量** | 交易笔数 | **<50 笔的统计没有说服力** |
| **Market change** | 期间大盘涨跌 | 策略收益应与此对比（BTC 涨 50% 你赚 5% 不如拿着不动） |
| Duration | 平均持仓时长 | 决定资金周转率 |

结果保存在 `user_data/backtest_results/`，可回看：

```bash
freqtrade backtesting-show
freqtrade backtesting-analysis      # 按币/按时段拆解
```

## 4.4 防骗指南：过拟合与未来函数

### 过拟合的信号

- 参数区间边缘的最优值（比如搜索范围 1~50，最优总是 1 或 50 → 范围设错了）；
- 换个时间段结果天差地别；
- 只在"参数组合恰好完美"的那段历史赚钱。

**对策**：参数少而钝（RSI 30 就够，不必 31.7）、分段回测（前半段调参、后半段验证）、样本外（out-of-sample）再测一次。

### 未来函数（lookahead）

典型错误：`dataframe["x"] = df["close"].rolling(20).mean()` 这类计算本身没问题，但如果你在**同一根 K 线内**用这根 K 线尚未产生的 `high/low/close` 去做决策，就是偷看未来。freqtrade 自带检测器：

```bash
freqtrade lookahead-analysis --strategy MyFirstStrategy --timerange 20250101-
freqtrade recursive-analysis --strategy MyFirstStrategy   # 检测自引用指标
```

（源码在 `freqtrade/optimize/lookahead_analysis*`、`recursive_analysis*`。）

## 4.5 Hyperopt：让机器帮你找参数

### 它在优化什么

Hyperopt 把"策略里的 `IntParameter/DecimalParameter`"当作搜索变量，反复跑回测，用一个**打分函数（loss）**评估每组参数，试图让 loss 最小。

```
参数组合 → 跑回测 → 得到一堆交易 → loss函数打一个分 → 尝试下一组
```

### 常用 loss 函数（`freqtrade/optimize/hyperopt_loss/`）

| loss | 文件 | 适合 |
|---|---|---|
| `CalmarHyperOptLoss` | calmar | 收益 ÷ 最大回撤 |
| `SharpeHyperOptLoss` | sharpe | 风险调整后收益（经典） |
| `MaxDrawDownHyperOptLoss` | max_drawdown | 最看重回撤控制 |
| `ProfitDrawDownHyperOptLoss` | profit_drawdown | **默认推荐**：收益+回撤平衡 |
| `OnlyProfitHyperOptLoss` | onlyprofit | 只看利润（新手易过拟合，慎用） |
| `ShortTradeDurHyperOptLoss` | short_trade_dur | 偏好快进快出 |

```bash
freqtrade hyperopt --strategy MyFirstStrategy \
    --hyperopt-loss ProfitDrawDownHyperOptLoss \
    --epochs 100 \
    --spaces buy sell \
    --timerange 20250101-20250601
```

- `--spaces buy sell` 只优化买入/卖出空间（不动 stoploss 等）；
- 结果在 `user_data/hyperopt_results/`，`freqtrade hyperopt-show -n 0` 查看最优组；
- 最优参数会写回策略（配合参数的 `load=True`），也可手动抄进策略。

### Hyperopt 的三个正确姿势

1. **先定 loss 再调参**——你想拿什么换什么（利润换回撤？）必须事先想清楚。
2. **epochs 不是越多越好**：搜索次数远大于参数组合数时，你就是在"挖掘噪音"。
3. **优化完必须换时间段再回测一次**，样本外不赚钱 = 白优化。

## 4.6 回测常见问题排查

| 症状 | 可能原因 |
|---|---|
| 0 笔交易 | 信号列名写错（应为 `enter_long` 而非 `buy`）、`startup_candle_count` 不足、timerange 内数据缺失 |
| 收益极高但只有几笔 | 参数过拟合 / 数据太少，看 Trades 数量 |
| 比预期差很多 | 忘了手续费与滑点、成交价假设（下一根开盘价）比想象的保守 |
| 报错 pairlist 不支持 | 回测用静态 pairlist：加 `"pairlists": [{"method": "StaticPairList"}]` |
| 回测结果和 dry-run 不一致 | 正常：dry-run 有实时订单簿/挂单延迟，回测是理想撮合 |
