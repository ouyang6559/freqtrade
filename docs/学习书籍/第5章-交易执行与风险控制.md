# 第 5 章 交易执行与风险控制

> 策略说"买"之后发生了什么？说"该卖了"之后又发生了什么？本章跟踪 `freqtradebot.py` 的下单/平仓/止损全链路，以及钱包、数据库如何配合。

---

## 5.1 开仓链路：从信号到成交

```
process() ⑫ enter_positions(free_slots)          freqtradebot.py:792
   │   过滤：去掉已有持仓的币、检查全局 pairlock
   ▼
create_trade(pair)                                freqtradebot.py:850
   │   取最新分析结果 dataprovider.get_analyzed_dataframe()
   │   调策略 get_entry_signal()（interface.py:1354）→ (LONG/SHORT, tag)
   │   无信号 → return False
   │   该币被锁？→ return False
   │   wallets.get_trade_stake_amount() 算这一笔投多少钱（见 5.4）
   ▼
execute_entry(pair, stake, ...)                   freqtradebot.py:1061
   │   get_valid_enter_price_and_stake() 定价（受 entry_pricing 配置约束）
   │   confirm_trade_entry 钩子：策略可最后一票否决（1111 行，默认放行）
   │   amount = stake / price * leverage          （1108 行）
   │   exchange.create_order(...)                 （1129 行）★ 真正/模拟下单
   │   dry_run 时走 create_dry_run_order（exchange.py:1195）本地伪造订单
   ▼
构造 Trade 对象写入数据库                          freqtradebot.py:1196
   │   字段：pair, stake_amount, open_rate, fee_open, open_date, strategy...
   ▼
通知 RPC（Telegram/FreqUI）："已开多 BTC/USDT"
```

之后由 `process()` 每轮的 `manage_open_orders`（`freqtradebot.py:1767`）跟踪订单状态，成交后 `update_trade_state`（第 2504 行）把实际成交量、手续费回写进 Trade。

### 关键设计

- **限价单不一定成交**：未成交的单会在后续轮询中被超时取消/改价（`handle_cancel_enter`，第 2042 行）——所以"有信号"不等于"有持仓"。
- **一币一仓**：`enter_positions` 会先把已有持仓的币从白名单剔除（第 806-809 行），避免同币重复开仓。
- **锁（PairLocks）**：连续亏损保护、protection 机制可临时封禁某币/全局（第 817 行检查）。

## 5.2 平仓链路：三道闸的判定顺序

```
process() ⑨ exit_positions(trades)               freqtradebot.py:1481
   对每个持仓：
   ├─ 有 stoploss_on_exchange？→ 先交给交易所托管止损（1505 行）
   └─ handle_trade(trade)                        freqtradebot.py:1527
        ├─ 取最新 K 线 → strategy.get_exit_signal()（interface.py:1321）
        ├─ exchange.get_rate() 取当前平仓参考价
        └─ _check_and_execute_exit()             freqtradebot.py:1562
             └─ strategy.should_exit(...)        interface.py:1419 ★ 三道闸
                  ① exit 信号 / custom_exit 钩子
                  ② ft_stoploss_reached → 止损
                  ③ min_roi_reached     → 止盈
                  （顺序即优先级；返回 ExitCheckTuple 列表）
             └─ execute_trade_exit()             freqtradebot.py:2247
                  下平仓单 → 更新 Trade(close_rate, exit_reason, is_open=False)
                  → 通知："已平仓，原因：stop_loss"
```

`should_exit` 中值得注意的细节（`interface.py:1462-1464`）：

```python
roi_reached = not (enter and self.ignore_roi_if_entry_signal) \
              and self.min_roi_reached(...)
```

即：如果同时出现入场信号且配置了 `ignore_roi_if_entry_signal`，就**先不满足止盈**（把资金留给新信号）。

### 止损的两种形态

| 形态 | 机制 | 适用 |
|---|---|---|
| 软止损（默认） | 机器人每轮自己算，触发后下市价单 | 需要机器人在线 |
| `stoploss_on_exchange: True` | 止损单**挂在交易所**，机器人宕机也生效 | 生产环境强烈建议（`handle_stoploss_on_exchange`，第 1632 行） |
| trailing stop | 价格涨则止损线抬升（`ft_stoploss_adjust`，interface.py:1524） | 趋势策略锁盈 |

**风控底线：宁可少赚，不能爆仓。止损永远在场。**

## 5.3 退出原因（exit_reason）速查

写进 `Trade.exit_reason`，报表按它统计，是复盘最重要的字段：

| 值 | 来源 |
|---|---|
| `roi` | 止盈表触发 |
| `stop_loss` | 硬止损 |
| `trailing_stop_loss` | 移动止损 |
| `exit_signal` | 你写的 `populate_exit_trend` |
| `custom_exit` | `custom_exit` 钩子返回 |
| `liquidation` | 强平（悲剧，说明风控失效） |
| `force_exit` | 人工 Telegram `/forceexit` |
| `partial_exit` | 部分减仓 |

## 5.4 钱包与仓位计算（`wallets.py`）

每笔投多少钱由 `get_trade_stake_amount`（第 385 行）决定：

```python
stake_amount = self._config["stake_amount"]
if stake_amount == "unlimited":                 # 你配置里的写法
    # (可用余额 + 已占用) / max_open_trades，再与可用余额取小
    stake_amount = self._calculate_unlimited_stake_amount(...)   # 347 行
return self._check_available_stake_amount(stake_amount, available)
```

- `stake_amount: "unlimited"` + `max_open_trades: 3` → **三等分资金**（你的 config 即如此）。
- `stake_amount: 100` → 固定每笔 100 USDT，余额不足直接抛 `DependencyException` 拒绝开仓。
- `get_available_stake_amount`（第 336 行）= `(总可用 + 在仓本金) × tradable_balance_ratio − 在仓本金`——`tradable_balance_ratio` 可以限制"最多拿多少比例的钱交易"，**留一部分稳定币是普通人的保命配置**。

## 5.5 数据库与重启恢复（`persistence/`）

- SQLite 文件就是你 `user_data/tradesv3.sqlite`。表 `trades`（`trade_model.py:1714`）与 `orders`（第 77 行）。
- `Trade` 关键字段（`trade_model.py:409-443`）：`is_open`、`open_rate/close_rate`、`stake_amount`、`amount`、`stop_loss`、`exit_reason`。
- **每次逻辑变更后 `Trade.commit()` 落库**（见 `process()` 第 ⑭ 步）。
- 重启后：`startup()`（`freqtradebot.py:262`）会
  - `stoploss_reinitialization` —— 你改了策略止损值后同步到旧持仓；
  - `startup_update_open_orders` —— 与交易所核对悬空订单；
  - 更新 funding fees / 强平价。
- **机器人停了 ≠ 仓位没了**：`check_for_open_trades`（第 369 行）会提醒你"还有 N 笔持仓，需人工处理或 `/start` 继续"。

## 5.6 监控币种筛选：Pairlist（`plugins/pairlistmanager.py`）

`_refresh_active_whitelist`（`freqtradebot.py:387`）每轮刷新白名单，筛选器可**级联**：

```json
"pairlists": [
    {"method": "VolumePairList", "number_assets": 30},   // 按成交量取前30
    {"method": "PriceFilter",     "low_price_ratio": 0.001}, // 过滤低价垃圾币
    {"method": "SpreadFilter",    "max_spread_pct": 0.5},    // 点差过大不交易
    {"method": "AgeFilter",       "min_pair_listed_days": 30} // 新币先观察
]
```

数据流：上一个筛选器的输出 → 下一个的输入。回测中一般用 `StaticPairList`（固定列表，保证历史一致性）。

## 5.7 运行模式与实盘前检查清单

| 配置 | dry-run（模拟） | live（实盘） |
|---|---|---|
| `dry_run` | `true` | `false` |
| 交易所 key/secret | 可以为空 | **必填，且只开交易权限、禁提现、绑 IP 白名单** |
| 下单 | 本地伪造订单 | 真实 API 调用 |
| 数据库/回测/通知 | 完全一致 | 完全一致 |

**实盘前 10 条检查清单：**

- [ ] dry-run 连续运行 ≥ 2~4 周，行为符合预期
- [ ] 多时段回测 + lookahead-analysis 通过
- [ ] `stoploss` 明确设置；考虑 `stoploss_on_exchange: true`
- [ ] `max_open_trades` 与 `stake_amount` 组合下，**全仓止损也不会伤筋动骨**
- [ ] `tradable_balance_ratio` 设置合理，留有生活费/储备
- [ ] pairlist 流动性充足（成交量过滤已开）
- [ ] 服务器时钟 NTP 同步（README Requirements 第 221 行强调）
- [ ] Telegram/告警可用，异常会通知你
- [ ] 数据库已备份策略，知道如何恢复
- [ ] 用可承受损失的小资金起步
