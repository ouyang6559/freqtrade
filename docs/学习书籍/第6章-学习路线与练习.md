### 第 4 周：守得住（模拟盘 + 复盘）

1. `dry_run: true` 启动 `freqtrade trade --strategy MyFirstStrategy`，跑满一周。
2. 配好 Telegram，熟悉 `/status` `/profit` `/balance` `/forceexit`（见 [telegram-usage](../telegram-usage.md)）。
3. 每天记录：开仓依据、平仓原因（exit_reason）、与回测预期的差异。
4. 复盘问题清单：
   - 有没有该止损没止损的时刻？（机器人离线？）
   - 限价单挂不上导致错过几笔？
   - 实际滑点和手续费吃掉多少？

**本周产出**：一份"回测 vs 模拟盘"差异分析——这是最值钱的一课。

## 6.2 练习题（按章汇总）

1. **概念**：用自己的话解释过拟合与未来函数，并各举一个"会导致回测虚高"的例子。
2. **源码**：在 `freqtradebot.py` 中画出 `process()` 的调用顺序图（第 2 章 2.4 节有答案）。
3. **策略**：实现"金叉入场 + 死叉出场 + RSI 过滤"的策略并回测（第 3 章 3.9）。
4. **回测**：同一策略，`stoploss` 从 -5% 到 -20% 各跑一次，记录收益与回撤变化，体会"止损宽度与盈亏的关系"。
5. **仓位**：`max_open_trades=3, stake_amount=unlimited, 总资金 3000`，算出每笔本金；再算全部触发 -10% 止损后的总资产。
6. **进阶**：给策略加 `confirm_trade_entry`，规则为"RSI > 80 时拒绝入场"，验证日志中出现 `User denied entry`（`freqtradebot.py:1123`）。
7. **进阶**：读 `exchange/exchange.py` 的 `create_dry_run_order`（1195 行），回答：模拟盘如何决定限价单是否成交？

## 6.4 用测试学 API（很多人不知道的捷径）

`tests/` 是最好的"活文档"——想知道某个方法怎么调用、边界条件是什么，直接搜测试：

```bash
grep -rn "confirm_trade_entry" tests/ | head
grep -rn "def test_should_exit" tests/
```

测试名通常形如 `test_xxx_condition_expected`，读测试比读文档更快理解行为。

## 结语（给小白的三句话）

1. **先跑通，再看懂；先模拟，再实盘。** 每一章的"动手练习"比读十遍正文有用。
2. **策略不神奇，风控才值钱。** 框架帮你执行纪律，而纪律是量化唯一确定的护城河。
3. **回测赚钱 ≠ 会赚钱。** 永远问：这笔收益经得起换一段行情、算上手续费滑点、扛得住回撤吗？
